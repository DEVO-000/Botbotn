# DEVORKS+ — деплой на Render (бесплатный тариф)

Пошаговая инструкция: как поставить бота на Render так, чтобы он работал
24/7, а данные НЕ ОБНУЛЯЛИСЬ при перезапусках платформы.

---

## Что получится

- Бот работает круглосуточно на бесплатном тарифе Render.
- Веб-облако «DEVO+ Облако» открывается по адресу бота
  (`https://имя-вашего-сервиса.onrender.com`) — отдельный хостинг и
  GitHub Pages НЕ нужны: приложение раздаёт сам процесс бота.
- Кнопка меню «☁️ DEVO+» и кнопка «🌐 Веб-облако» появятся в Telegram САМИ —
  Render отдаёт свой адрес в переменную `RENDER_EXTERNAL_URL`, а бот
  подхватывает её (волна 22.22).
- Данные защищены от «обнуления» диска: база постоянно зеркалится в ваш
  приватный канал (подробнее ниже), при старте на пустом диске бот сам
  вспоминает всё из канала.

## Что понадобится заранее

1. Аккаунт GitHub и аккаунт Render (удобно войти через GitHub).
2. Токен бота `BOT_TOKEN` (от @BotFather).
3. ID каналов-хранилищ через запятую — `STORAGE_CHANNELS`
   (например `-1001234567890`). Это ТЕ ЖЕ каналы, что подключены в
   🛠️ Панели разработчика → ☁️ Хранилище: база и файлы живут в них.
4. Ваш числовой ID — `DEVELOPER_ID`.
5. Если задавали `DB_KEY` — задайте ТОТ ЖЕ. Если не задавали — не задавайте
   и на Render (шифрование тогда привязано к `BOT_TOKEN`, и старая база
   читается сама). Главное правило: `BOT_TOKEN` — тот же, что был.
6. Если пользовались: `GROQ_API_KEY` (ИИ), `TELETHON_SESSION` (файлы до 2 ГБ),
   `DEEPSEEK_API_KEY` (автоматизация).

⚠️ ВАЖНО О ПРИВАТНОСТИ: в GitHub загружайте ТОЛЬКО файлы из архива релиза
(`main.py`, `requirements.txt`, `miniapp/index.html`, `.gitignore`).
Файлы данных (`users.json` и другие `.json`) содержат личные данные
школьников — загружать их в репозиторий НЕЛЬЗЯ, им там и не нужно: база
восстанавливается из вашего канала. `.gitignore` дополнительно страхует.

## Шаг 1. Репозиторий на GitHub

1. github.com → New repository → имя, например `devorks-bot` → **Private**
   → Create.
2. На странице репозитория нажмите «uploading an existing file» и перетащите
   файлы из архива релиза: `main.py`, `requirements.txt`, `.gitignore`,
   папку `miniapp` с файлом `index.html` внутри, `ЧТО_НОВОГО.md` (по желанию).
3. Commit changes.

## Шаг 2. Сервис на Render

1. render.com → **New +** → **Web Service** → подключите репозиторий
   `devorks-bot`.
2. Настройки:
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python main.py`
   - **Instance Type:** Free
3. Раскройте **Advanced → Add Environment Variable** и добавьте:

   | Ключ | Значение |
   |------|----------|
   | `BOT_TOKEN` | токен от @BotFather |
   | `STORAGE_CHANNELS` | `-100…` вашего канала-хранилища (несколько — через запятую) |
   | `DEVELOPER_ID` | ваш числовой ID |
   | `DB_KEY` | только если задавали раньше, ТОТ ЖЕ |
   | `GROQ_API_KEY` | если пользовались ИИ |
   | `TELETHON_SESSION` | если пользовались Сейфом >49 МБ |

   `PORT` добавлять НЕ нужно — Render подставит его сам, бот его читает.
4. Там же в **Advanced → Health Check Path** укажите: `/health`
5. **Create Web Service** → дождитесь деплоя (5–10 минут, смотрите логи).

## Шаг 3. Проверка

В логах деплоя должны появиться строки:
- `env-бутстрап хранилища: добавлено каналов …` (каналы из `STORAGE_CHANNELS`);
- `Keep-alive сервер запущен на порту …: /health + мини-апп «DEVO+ Облако»`;
- при первом старте на пустом диске — `cdb boot: ВСПОМНИЛИ ВСЁ ИЗ КАНАЛА`.

Затем:
1. Откройте `https://имя-сервиса.onrender.com/health` — должен быть ответ OK.
2. Откройте `https://имя-сервиса.onrender.com/` — видна заставка «DEVO+ Облако».
3. В Telegram: `/start` боту → кнопка меню «☁️ DEVO+» открывает облако.

## Почему данные НЕ обнуляются (честно, как это устроено)

Диск на бесплатном тарифе эфемерный: при перезапуске сервиса он стирается.
Поэтому бот давным-давно (волны 8/10/11/17/22.14) устроен так:

1. **Режим «База в канале» включён по умолчанию** — канал первичен, диск —
   только кэш. Каждая запись в базу помечает файл «грязным».
2. Раз в 30 секунд (и не чаще одного слива в 20 секунд — защита от шторма)
   бот собирает ВСЁ в zip-снапшот, заливает в каналы и ЗАКРЕПЛЯЕТ его;
   предыдущий снапшот стирает, чтобы в канале оставался один актуальный.
3. Ключевые события Сейфа (пароль, вопросы, шифрование) сливаются немедленно.
4. При остановке — финальный слив; раз в сутки — полный бэкап с историей.
5. При старте на пустом диске: каналы бот вспоминает из `STORAGE_CHANNELS`,
   видит пустую базу и САМ восстанавливает всё из закреплённого снапшота
   (пользователей, классы, ДЗ, Сейф — пароль тот же, таймеры, настройки).

Максимум возможной потери при внезапном сбое — изменения за последние
~20–30 секунд перед ним. Это честный предел, лучше не делает ни один
бесплатный хостинг.

## Про sw.js (ваш вопрос)

Service Worker — это кэш В БРАУЗЕРЕ пользователя. На сервер, где диск
обнуляется, он повлиять не может, а закэшированный список файлов показал бы
файлы, которых уже нет. Поэтому sw.js НЕ подключён — данные защищаются
по-настоящему, на сервере (см. выше). Интерфейс и так открывается быстро.

## Ограничения бесплатного Render (честно)

- Сервис может заснуть после 15 минут без запросов. Бот пингует свой же
  `/health` каждую минуту (локально и по внешнему адресу), поэтому не спит.
  Часов в месяце хватает (750 > 744) на один сервис 24/7.
- Render иногда сам перезапускает сервисы (обновления платформы) —
  восстановление из канала сработает автоматически, проверьте после
  рестарта Сейф/классы/ДЗ.
- После сна первый ответ может занять 30–60 секунд (холодный старт).
- Tesseract (OCR на фото) на Render системно не ставится — бот честно
  перейдёт на вижн-модель Groq, функция не сломается.
- Файлы >2 ГБ не пропускает сам Telegram; >49 МБ через веб требуют
  `TELETHON_SESSION` в переменных окружения.

## Обновление бота

Загрузите новые версии файлов в репозиторий GitHub (Edit → вставить →
Commit) — Render сам передеплоит, а базу бот вспомнит из канала.
